  ◆ 按顶点门限回退 vanilla（恢复 1.21.4 的「too small」语义） (工作量 小)
    做法: 在 ItemFeatureRendererMixin 取到 quads 后，累加总顶点数（quads.size()*BakedQuad.VERTEX_COUNT），低于阈值（例如单 submit < 8~16 顶点）时不接管，直接 return 交还原版 putBakedQuad。26.1 只需在既有入口加一个 early-return 分支，不新增 mixin。
    可行性: 高。改动局限在 ItemFeatureRendererMixin 一个文件、几行；阈值可先用 1.21.4 的语义等价物（小模型不加速）
    风险: 低。最坏情况是退回现状（等于关闭物品加速）；不会破坏渲染正确性，因为未接管的 submit 走原版路径
  ◆ 合并同一 ItemSubmit 的所有 quad 为一个 per-model mesh (工作量 中)
    做法: 把 AcceleratedQuadsRenderer.render 的内层「每 quad 一个 mesh」改为「每个（extension, RenderType）一个 mesh」：在一个 meshCollector 里连续 addVertex 该 submit 的全部 quad，flush 一次，build 一个含 N×4 顶点的 mesh 并缓存（键为 quad 列表签名/模型身份）。这样 1 个物品 = 1 个 mesh 实例，实例数降到 1/230（本场景）。
    可行性: 中。AcceleratedQuadsRenderer.render 已在同一 extension/transform 下拿到整个 quad 列表，改动范围可控；难点是缓存键——需用整个 quad 列表的几何做键（可复用 MeshData 的 merges 去重），而非单个 BakedQuad 实例
    风险: 中。合并后 tint 逐层不同（tintIndex 不同）需拆 mesh，退回 1.21.4 的按 tint layer 聚合逻辑；缓存键变大可能带来 map 开销。理论上正确性可控
  ◆ 移植 1.21.4 的整模型烘焙路径（SimpleBakedModelMixin 接线） (工作量 大)
    做法: 把 26.1 已存在但未注册的 SimpleBakedModelMixin / ItemRendererMixin / MultipartBakedModelMixin / WeightedBakedModelMixin 加入 acceleratedrendering.feature.items.mixins.json，并在 26.1 的提交渲染链路（ItemSubmit 是否携带 bakedModel 引用）里补上 renderItemFast 入口。
    可行性: 低-中。26.1 的 ItemFeatureRenderer.renderItem 只拿到 SubmitNodeStorage.ItemSubmit（含 pose/quads/tintLayers，不一定含 bakedModel 身份），整模型入口需要额外在提交段（ItemStackRenderState.submit）注入，工作量远大于前两个方案
    风险: 高。26.1 物品渲染已重构为「提交-渲染两段式」，1.21.4 的注入点(ItemRenderer.renderItem)不存在；盲接可能破坏其它 RenderType 分组逻辑
  ◆ 物品 mesh 改走 CLIENT 直传（addClientMesh memCopy） (工作量 小)
    做法: 把 AcceleratedQuadsRenderer 建 mesh 时从 AcceleratedEntityRenderingFeature.getMeshType() 换成 AcceleratedItemRenderingFeature.getMeshType() 配置，并设成 CLIENT；ClientMesh.write → addClientMesh 直接把网格字节 memCopy 进顶点缓冲，跳过 compute 上传的实例循环。
    可行性: 中。需修死配置 bug（AcceleratedQuadsRenderer.java:133-135），实测 CLIENT 对每-quad mesh 是否更快未知
    风险: 中-高。addClientMesh 每实例做一次 vertexSize×4 字节 memCopy + varyingSize×4 写（AcceleratedBufferBuilder.java:373-409），对 4 顶点 mesh 可能反而更慢；且 CLIENT 只对 dynamic/走 vertexBuffer 的 RenderType 生效，可能大面积不可加速
